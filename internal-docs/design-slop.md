# Design Slop

These visual patterns make an interface look generated instead of intentional. Every element on screen must earn its place through utility and clarity.

Tags and badges
Pill labels and chips often decorate text instead of communicating real state. If information matters, convey it through hierarchy, a title, or direct status. Remove decorative tags.

Italicized words
Italics weaken voice when used for casual emphasis in product copy. Use plain phrasing, natural sentence flow, or font weight instead. Reserve italics strictly for publication titles and verbatim quotes.

Display serif with negative letter spacing
Compressed display serifs are stylistic posturing rather than purposeful design decisions. Use the standard sans-serif type tokens at normal tracking. Never apply negative letter spacing to user interface text.

Over-the-top detailed UI
Heavy outer glows, multi-stop gradients, procedural grain, and decorative micro-lines add visual noise. Strip decorative flourishes until the interface breaks, then restore only what provides functional clarity.

Dividers
Lines slicing across views create visual friction. Rely on whitespace, alignment, and grouping to organize content instead of drawing horizontal rules or vertical pipe dividers between elements.

Multiple color shades and opacities
Scattering near-identical grays, varying alpha levels, and multi-colored accents fragments visual hierarchy. Stick to established theme tokens: one accent color and at most two text hierarchy levels per screen.

Containers with borders
Cards inside cards, bordered wrappers, and dashed frames trap content in boxes. Let content breathe directly on surfaces. When separation is necessary, use a subtle surface step without an outline border.

Diagrams
Complex diagrams often obscure simple concepts behind boxes and arrows. Prefer a direct sentence or a concise list. When a diagram is truly essential, keep it under five nodes with zero decorative styling.

Code breadcrumbs
Monospace paths, raw IDs, and function names clutter user-facing interfaces. Present human outcomes and readable titles, leaving code identifiers and technical paths to developer logs.

Section numbering
Numbered headings add administrative clutter. Name a section directly by what it contains, or remove the heading entirely.

Related patterns seen in this app
Avoid uppercase monospace headers, subtitles placed under every list item, and jargon like synthesize, dynamic, or engine. Use plain verbs, sentence case, and concise single-line descriptions.
